# Nickey44A-PAD のキーとトラックパッド

## キーの対応

移植元は [torabo-tsuki LP の `yamaryu211_main`（e45ba15）](https://github.com/yamaryu211/zmk-keyboard-torabo-tsuki-lp/blob/e45ba157f6ef610b51c636ebd35506437945f9b1/config/keymap.keymap) の S 配列。上3段は Q〜T・Y〜P の列を基準に合わせた。Bの右とNの左は全レイヤーで無割り当て。右親指列の右端はキーボード設定レイヤーでStudioのロックを解除する。torabo の3段目中央2キーは除外した。

| 外側の列 | 左手 | 右手 |
|---|---|---|
| 上段 | Esc | Backspace |
| 中段 | 左Command（Mac）／左Control（Windows） | Enter |
| 下段・短押し | 言語2 | 言語1 |
| 下段・長押し | 使用中のOSの数字レイヤー | 使用中のOSのファンクションレイヤー |

| 最下段を左から | 左1 | 左2 | 左3 | 右1 | 右2 | 右3 |
|---|---|---|---|---|---|---|
| タップ | Alt | Delete | Space | Enter | Backspace | 空白 |
| 長押し | Alt | Ctrl（Macは⌘） | Shift | 数字 | 記号 | 空白 |

torabo の最下段12キーのうち、中央寄りの5キー（位置35〜39）を採用した。コンボは S+D で Tab、D+F で Shift+Tab、Q+W で Esc、A+S で Caps Lock、J+K またはコンマ＋ピリオドで中クリック。

自動マウスレイヤー（AML）は初期設定でオフ。トラックパッドを動かした直後も通常配列で入力できる。以前の動作に戻すには、`config/nickey_layers.h` の `NICKEY_AUTO_MOUSE_LAYER` を `1` にして再ビルドする。左右のパッドとマウスキーからの自動切替が有効になり、AML中はJ・コンマが左クリック、K・ピリオドが右クリックになる。

親指列から外れた言語キーと設定操作には次の経路がある。

| 操作 | 結果 |
|---|---|
| Enterを保持し、Tをタップ／保持 | 言語1／ファンクションレイヤー |
| Enterを保持し、Gをタップ | 言語2 |
| 右親指のEnterを保持してから、その隣の親指Backspaceも保持 | キーボード設定レイヤー |
| 設定で上から3段目の左端／右端を押す | 左側／右側をブートローダーモードにする |
| 設定で H / J / K / L / 右隣のキー | BT 0 Windows / 1 Mac / 2 iPad / 3 iPhone / 4 iPad mini |
| 設定で W / E | 現在の接続先にWindows / Mac配列を保存。USBでも使用可 |
| 設定で右親指列の右端、または Q | Studioロック解除 |
| 設定で R | USB・BLE出力切替 |

## 左右共通のジェスチャー

| 指の操作 | 動作 |
|---|---|
| 1本指で移動／タップ | カーソル移動／左クリック |
| 1本指でタップし、同じパッドにすばやくもう一度触れて、その指を滑らせる | 2回目の指の移動でドラッグ開始。端では指を置き直して続行できる |
| 2本指で上下／左右に移動 | 縦／横スクロール。下に動かすとページの上へ、上に動かすとページの下へ移動。縦方向は指を離すと慣性あり |
| 2本指でタップ | 右クリック |
| ピンチイン／アウト | 対応アプリで縮小／拡大。WindowsはCtrl、Macは⌘と、マイナス／イコールの組み合わせを送信 |

対象にカーソルを合わせて1回タップし、指を離してから300 ms以内に同じパッドに触れる。2回目はそのまま動かすとドラッグ、短くタップして離すと通常のダブルクリックになる。ドラッグ中にパッドの端に来たら、指を離して250 ms以内に同じパッドの中央に置き直すと、そのまま運び続けられる。指を離したまま250 ms経つとドロップする。すぐにドロップしたいときは、その猶予中に同じパッドを1回軽くタップする。

2本指スクロールは、2本をほぼ平行に滑らせたときの平均移動距離がセンサー座標で24ピクセルを超えると認識する。縦または横から35度以内で開始できる。認識後は小さな移動も軸ごとに積算し、20単位でホイール1単位を出力する。[Azoteqの仕様書 §6.5](https://www.azoteq.com/images/stories/pdf/iqs5xx-b000_trackpad_datasheet.pdf)

Windowsは標準のマウスホイール方向、Macは「マウス → ナチュラルなスクロール」がオンの状態を前提とする。Mac配列では縦・横のホイールの符号を反転する。配列に連動するため、toraboのレイヤー16による手動の方向フラグは不要。数字・ファンクションなどのレイヤーでもパッドの基本操作は共通。[Appleのマウス設定](https://support.apple.com/ja-jp/guide/mac-help/mh29222/mac)

## TPS43の比較用ファームウェア

`zmk-workspace` の `nix develop` 内で、表の名前を `just flash` に渡す。左だけをUSBでつないでブートローダーモードにし、左を書き込む。続いて右だけをつないで同じ手順で右を書き込む。各段階の左右を組み合わせて試す。

| 段階 | 左 | 右 | 比較する操作 |
|---|---|---|---|
| 基準 | `nickey44a_l` | `nickey44a_r` | 両側で短くゆっくり2本指を滑らせ、縦・横それぞれの出だしを確認 |
| 1 ピンチ無効 | `no_pinch_l` | `no_pinch_r` | 基準と同じ操作を繰り返し、スクロールの開始が早まるか確認。変更はセンサーのズーム認識だけ |
| 2 カーソル加速 | `nickey44a_l` | `cursor_accel_r` | 両側で小さい対象にゆっくり合わせる操作と、画面を速く横切る操作を比較。ピンチも有効 |
| 3 指を離す順序への対策 | `finger_guard_l` | `finger_guard_r` | 段階2に追加。スクロールやピンチの後、片方の指だけを残して少し動かしてもカーソルがずれず、全指を離して触れ直すと動くか確認 |
| 4 右端の縦スクロール | `edge_scroll_l` | `edge_scroll_r` | 段階3に追加。各パッドの右端から1本指で上下に滑らせる。中央から端へ滑らせたときと、ドラッグ中に端に置き直したときはカーソルが動く |

段階1で開始しやすくなれば、次の調整候補はピンチを有効に戻したうえでの `zoom-initial-distance`。スクロールとピンチが競合するかを切り分ける比較なので、段階2に進むときは左も基準版へ戻す。

段階2の加速は低速時0.8倍から高速時2.2倍。左右のパッドと各軸で速度と端数を独立に扱う。段階4はタッチ開始時の絶対Y座標を使い、座標の小さい側6%を物理的な右端と想定した。端の向きと幅は両側の実機で要確認。センサーの座標仕様は [Azoteq IQS5xx-B000 §5.2.3、§8.9](https://www.azoteq.com/images/stories/pdf/iqs5xx-b000_trackpad_datasheet.pdf) を参照。

段階1を再ビルドして書き込む例。

```sh
just build no_pinch
just flash no_pinch_l
# 左を外し、右をUSBでつないでブートローダーモードにする
just flash no_pinch_r
```

段階2以降の再ビルドはそれぞれ `just build cursor_accel`、`just build finger_guard`、`just build edge_scroll`。基準版の左右は `just build 'nickey44a_[lr]$'` で作れる。

## 配線と検証

両側とも SDA は P0.09、SCL は P1.01、RDY は P0.15、NRST は P0.19。I²Cアドレスは各MCUのバス上で `0x74`。左はイベントをそのまま BLE split の reg 0 で右へ送り、右centralで両パッドに同じ向き補正とOS別の変換を適用する。慣性の状態はパッドごとに独立している。

左右のUF2をビルドした後、生成されたDevicetreeとKconfigを次のコマンドで確認できる。

```sh
python3 scripts/check_dual_tps43.py --zephyr-base "$ZEPHYR_BASE" \
    --left-build /path/to/left-build --right-build /path/to/right-build
```

実機では、左右それぞれのカーソルの向き、Windows・Macでの縦横スクロール、ピンチとタップの感度を確認する。左パッドの取り付け向きには右パッドと同じ向きを仮定した。Studioに以前のキーマップを保存している場合は、新しい割り当てを試す前にStudioのキーマップをファームウェア既定値へ戻す。
